Configuration

Reasoning budget

Choose one policy, then keep exceptions only where answer quality needs them. Savings uses low for verified models and none for Mistral, keeping off/minimal settings intact. Required reasoning and models without a verified control are preserved. This reduces reasoning effort, not the model's token price; savings and quality need measurement.

Preview applies to the next saved configuration, including the Reasoning switch, API, Watches and Topics using these models. Use Save Changes to activate; Reload discards edits. Memory edit retains its fixed task setting.

Saved configuration · technical details

Per-provider model lists shown in the app's model pickers (row order = picker order). Default sets the Free-tier preselection. Premium marks Pro-only models. Consensus offers the model in the Consensus picker. In use shows which defaults, presets, Watches or judges currently reference a model. Nothing is silently re-added: update those references when removing a model.

Preset Model Sets

Each preset selects exactly six answer models from the available families and the final Consensus engine. Daily and Balanced accept Free-tier models only; High Quality is always Pro-only.

Judges (Differences, claim marks, Resolve)

Judge models per provider family for the Differences engine, the claim-coverage judge behind the inline claim marks, and the Resolve round. Standard engines get the Standard judge, Pro engines the Pro judge (always run at provider-compatible reduced effort).

Judge assignment

Which family judges which Consensus engine. Auto picks the first family with an available API key from the priority order (OpenAI first, also for OpenAI engines); a manual pick is preferred first and falls back to Auto if its key is unavailable.

Source Checks

Models that check factual contradictions against existing sources. Default: Gemini 3.5 Flash-Lite. Changes apply to new checks; checks already in progress keep their original model choices.

Optional second model if the primary check is unavailable. Disabled until configured. Choose a different model from the primary. Gemini 3.5 Flash-Lite is a recommended fallback when another model is primary. Existing evidence limits still apply.

Chat Memory

Model that compresses older turns of a conversation into the structured memory a follow-up is answered with. It runs once per turn from the third turn on — a JSON extraction job, not a reasoning one, so a cheap model is usually the right pick. The family always follows the turn's Consensus engine, because with own API keys only that provider's key is available; you choose the model inside each family. If the call fails, the server falls back to a deterministic summary without an LLM.

Consensus Engines

Ordered list shown in the app's Consensus picker. Aliases (e.g. Gemini-Pro) resolve to a provider model server-side and follow config updates automatically; direct model IDs must exist in a provider list on the Models tab. The first entry is preselected for new users.

Daily token allowance

One account per user and UTC day for Compare, Consensus, Reasoning runs and Agent (input + output tokens, reasoning included). A run starts only when the tokens left cover its expected run cost below; it then books what it measured and may end slightly below zero. Agent reserves before every call. Who may use Agent is unchanged (Pro and Admin). Changes apply within 30 seconds.

Input, output and Watch limits per account tier. Limits apply after the daily reset. The Reasoning switch is open to every tier; its output cap is the larger of the tier's output limit and Reasoning output tokens.

Account tier

Free — base models, small daily quota, attachments. Plus — exactly the Free model choice, but Resolve rounds, more file storage and the largest run quota. Give this to testers: they cannot trigger a frontier-model cost. Pro — everything, including frontier models. A change takes effect immediately; every change is written to an audit log.

Accounts above Free

Every account currently tagged Plus or Pro, plus the most recent tier changes.

Consensus API keys

Issue a key for an active, e-mail-verified Firebase user. The key inherits that UID's tier and its daily token allowance (shared with the app). All v1 runs use the six server-selected Balanced-preset families, including DeepSeek processing in China. Run content expires after 30 days. Only a SHA-256 hash is stored; the full key is shown exactly once and should be copied directly into a secret manager.

Former Publisher pages

Pages the retired Scheduled Publisher created, each with a weekly Free-model Watch that still reruns until you pause it. Deleting a page also removes its Watch schedule, Watch history, and follower subscriptions.

Reported pages first (review-priority, then report count). Index puts a page into sitemap-shares.xml and removes its noindex — only do this for eligible pages. Delete permanently removes the page and all Watch-bound data.

Consensus Watch diagnostics

Test SMTP independently or start an active watch immediately through the normal leased scheduler path. Manual runs make real model calls, write history, advance their schedule, and apply their configured e-mail rule.

Watch models by user tier

Choose one answer model per enabled provider and a separate Consensus engine for the Free/Plus profile and the Pro profile. Plus deliberately uses the same model profile as Free; only its limits and optional daily interval differ. At least two answer providers are required. Premium models stay listed for Free/Plus but are locked (“Pro only”). An arrow (→) marks a variant that sends a different API model. The Actually runs row shows what the next run will really use — a configured provider that gets skipped is named there with its reason. Personal watches follow the owner's current tier.
